## วิธีใช้เอกสารนี้

**ระดับความสำคัญ**

| สัญลักษณ์ | ความหมาย | ถ้าไม่ผ่าน |
|---|---|---|
| 🔴 | **ต้องผ่าน** | **ห้ามเปิดใช้งานจริง** ต้องแก้ให้ผ่านก่อน |
| 🟡 | ควรผ่าน | เปิดใช้ได้ แต่ต้องมีแผนรับมือหน้างาน |
| 🟢 | ดีถ้ามี | บันทึกไว้ทำรอบถัดไปได้ |

**วิธีบันทึกผล** — ให้เติมในช่อง "ผล" ของแต่ละตาราง

- `✅` = ผ่าน
- `❌` = ไม่ผ่าน (เขียนสิ่งที่เจอในช่อง "หมายเหตุ" ให้ละเอียดที่สุด: กดอะไร เห็นอะไร คาดว่าควรเห็นอะไร)
- `⚠️` = ผ่านแบบมีเงื่อนไข
- `—` = ยังทดสอบไม่ได้ (ระบุเหตุผล)

> **ขอความกรุณา** — ข้อที่ไม่ผ่าน ถ้าถ่ายภาพหน้าจอแนบมาด้วยจะแก้ได้เร็วขึ้นมาก
> โดยเฉพาะข้อความ error ที่ขึ้นบนหน้าจอ

## ส่วนที่ 0 · สิ่งที่ต้องเตรียมให้พร้อมก่อนเริ่ม UAT

ถ้าข้อใดข้อหนึ่งในส่วนนี้ยังไม่พร้อม **จะมีบางหมวดทดสอบไม่ได้เลย** โปรดเช็กให้ครบก่อน

| # | สิ่งที่ต้องเตรียม | ทำไมถึงจำเป็น | สถานะ |
|---|---|---|---|
| P-01 | **เว็บขึ้น URL จริงที่เป็น HTTPS** (เช่น `register.tnn.co.th` หรือ URL ของ Vercel) | 🔴 เบราว์เซอร์ **บล็อกกล้องและ Service Worker บน http** — ถ้าไม่ใช่ HTTPS หมวด D ทดสอบไม่ได้เลยแม้แต่ข้อเดียว | ☐ |
| P-02 | **ฐานข้อมูล Supabase จริง** (Singapore) พร้อม migration + seed | 🔴 ทุกหมวดต้องใช้ | ☐ |
| P-03 | **`RESEND_API_KEY`** และโดเมนผู้ส่งที่ตั้ง **SPF + DKIM + DMARC** ครบแล้ว | 🔴 ถ้าตั้ง DNS ไม่ครบ อีเมลจะตกถัง Junk ทั้งหมด → หมวด C ทดสอบไม่ได้ (อ้างอิงคำถาม **Q14**) | ☐ |
| P-04 | **กุญแจ reCAPTCHA v3** (site key + secret key) | 🟡 ถ้าไม่มี ระบบจะข้ามการตรวจ bot → ข้อ B-22 ทดสอบไม่ได้ | ☐ |
| P-05 | **`HASH_SALT`** ตั้งค่าแล้วบนเซิร์ฟเวอร์จริง | 🔴 ระบบจะไม่ยอมทำงานถ้าไม่มี — ตั้งใจให้เป็นแบบนั้นเพื่อกัน IP ดิบหลุดลงฐานข้อมูล | ☐ |
| P-06 | **มือถือ Android จริง 1 เครื่อง** (Chrome เวอร์ชันล่าสุด) | 🔴 หมวด D และ F | ☐ |
| P-07 | **iPhone จริง 1 เครื่อง** (Safari เวอร์ชันล่าสุด) | 🔴 หมวด D และ F — iOS เข้มงวดเรื่องกล้องมากกว่า Android | ☐ |
| P-08 | **เครื่องพิมพ์จริงที่จะใช้วันงาน** + กระดาษ/สติกเกอร์ที่จะใช้จริง | 🔴 หมวด D (บัตรห้อยคอ) — ต้องรู้ยี่ห้อ/รุ่นก่อน (อ้างอิงคำถาม **Q16**) | ☐ |
| P-09 | **บัญชีทดสอบ 3 บัญชี** — อีเมล Gmail 1 · Outlook/Hotmail 1 · iCloud หรือ Yahoo 1 | 🔴 หมวด C — แต่ละค่ายกรองอีเมลไม่เหมือนกัน | ☐ |
| P-10 | **บัญชีเจ้าหน้าที่ 2 บัญชี** (เพื่อทดสอบสแกนพร้อมกัน 2 เครื่อง) | 🔴 ข้อ D-38 | ☐ |
| P-11 | **ไฟล์กราฟิกงานจริง** — โลโก้ผู้จัด · โปสเตอร์ · บล็อกชื่องานบนบัตร · แถบโลโก้ผู้สนับสนุน | 🟡 ถ้ายังไม่มี จะทดสอบด้วย placeholder สีส้มไปก่อน แต่ **ขนาดบัตรจริงต้องวัดซ้ำ** เมื่อใส่กราฟิกจริง (อ้างอิงคำถาม **Q8**) | ☐ |
| P-12 | **ตกลงกันว่าจะล้างข้อมูลทดสอบเมื่อไหร่** และใครเป็นคนล้าง | 🔴 ข้อมูลจากการทดสอบ **ห้ามปนกับข้อมูลผู้ลงทะเบียนจริง** | ☐ |

> ### ⚠️ ข้อควรระวังก่อนเริ่ม
> การทดสอบเช็คอินและการทดสอบโควตา **จะทิ้งข้อมูลไว้ในฐานข้อมูล**
> ถ้าจะทดสอบซ้ำรอบสอง ต้องล้างก่อน ไม่งั้นรอบสองจะขึ้น "เช็คอินไปแล้ว" ซึ่งเป็นพฤติกรรมที่ถูกต้อง แต่ทำให้เข้าใจผิดว่าระบบพัง
>
> ```sql
> DELETE FROM check_ins;
> UPDATE event_sessions SET checked_in_count = 0;
> ```
